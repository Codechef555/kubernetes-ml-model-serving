# ☸️ Kubernetes-Based Model Serving & Autoscaling — Implementation Roadmap

## Implementation Sequence

Follow this exact order when creating and implementing the project. Complete each step before moving to the next.

### Phase 1: Project Initialization and Environment Setup

### 1. `steps.md`
Defines the complete implementation roadmap, including the sequence of files to create, commands to execute, and testing activities.

### 2. `requirements.txt`
Defines the Python dependencies required for machine learning, API development, model serialization, testing, and monitoring integration.

### 3. `.gitignore`
Specifies files and directories Git should exclude, including Python virtual environments, cache files, generated model artifacts where appropriate, local secrets, and temporary files.

### 4. `.dockerignore`
Excludes unnecessary files from Docker build contexts, such as virtual environments, Git metadata, test caches, and local development artifacts.

### 5. `app/__init__.py`
Initializes the application directory as a Python package.

### 6. `ml/__init__.py`
Initializes the machine learning directory as a Python package.

### 7. `tests/__init__.py`
Initializes the test directory as a Python package.

---

## Phase 2: Machine Learning Model Development

### 8. `ml/train.py`
Loads the customer churn dataset, performs preprocessing, trains a machine learning classification model, evaluates its performance, and saves the trained model.

### 9. `ml/model.pkl`
Stores the serialized trained machine learning model for later use by the prediction API. Generated by executing `ml/train.py`.

### 10. `ml/metrics.json`
Stores model evaluation metrics such as accuracy, precision, recall, F1-score, and other relevant evaluation results. Generated during model training.

---

## Phase 3: FastAPI Model Serving

### 11. `app/schemas.py`
Defines request and response schemas using Pydantic to validate incoming prediction data and standardize API responses.

### 12. `app/model.py`
Loads the trained machine learning model and provides reusable prediction functionality.

### 13. `app/main.py`
Creates the FastAPI application and implements prediction, health-check, model information, and readiness endpoints.

### 14. `tests/test_model.py`
Contains unit tests for model loading, input validation, prediction functionality, and model output.

### 15. `tests/test_api.py`
Tests the FastAPI endpoints, including successful predictions, invalid input handling, health checks, and error responses.

### 16. Local API Testing
Executes the FastAPI application locally using Uvicorn and verifies its endpoints through Swagger UI and automated tests.

---

## Phase 4: Docker Containerization

### 17. `Dockerfile`
Defines the container image configuration for the machine learning API, including the Python base image, dependencies, application files, exposed port, and startup command.

### 18. `.dockerignore` Verification
Ensures unnecessary development files are excluded from the Docker build context.

### 19. Docker Image Build
Builds the machine learning API image using the Docker CLI and verifies that the image is created successfully.

### 20. Docker Container Testing
Runs the container locally, tests prediction endpoints, verifies application startup, and checks container logs.

---

## Phase 5: Kubernetes Deployment

### 21. `k8s/namespace.yaml`
Creates a dedicated Kubernetes namespace to isolate the machine learning serving application and its resources.

### 22. `k8s/configmap.yaml`
Stores non-sensitive application configuration, such as environment settings and model-related configuration values.

### 23. `k8s/deployment.yaml`
Defines the Kubernetes Deployment, including the Docker image, pod replicas, container ports, resource requests, resource limits, and health probes.

### 24. `k8s/service.yaml`
Creates a Kubernetes Service to expose the prediction API and distribute incoming traffic across available application pods.

### 25. `k8s/hpa.yaml`
Configures the Horizontal Pod Autoscaler to increase or decrease the number of application replicas based on CPU utilization.

### 26. `k8s/secret.yaml` (Optional)
Defines a Kubernetes Secret for sensitive configuration when required. Real credentials must not be committed to Git.

### 27. Kubernetes Deployment Execution
Applies the Kubernetes manifests and verifies the deployment, pods, services, and application health.

---

## Phase 6: Autoscaling and Load Testing

### 28. `load-testing/requirements.txt`
Defines the dependencies required for generating HTTP traffic and conducting load tests.

### 29. `load-testing/load_test.py`
Generates concurrent prediction requests to simulate application traffic and evaluate the behavior of the Kubernetes deployment.

### 30. HPA Verification
Uses Kubernetes metrics to verify CPU utilization and observe automatic scaling of application replicas under increased workload.

### 31. Autoscaling Experiment Results
Records replica counts, CPU utilization, request volume, response times, and scaling observations under different workloads.

---

## Phase 7: Monitoring and Observability

### 32. `monitoring/prometheus.yml`
Defines Prometheus scrape configuration for collecting application and infrastructure metrics from supported monitoring targets.

### 33. `monitoring/grafana/datasources/prometheus.yaml`
Configures Prometheus as a Grafana data source.

### 34. `monitoring/grafana/dashboards/ml-serving-dashboard.json`
Defines a Grafana dashboard for monitoring API requests, response times, errors, CPU usage, memory usage, and application performance.

### 35. Monitoring Deployment
Deploys the monitoring components and verifies that Prometheus collects metrics and Grafana displays the available metrics.

---

## Phase 8: Evaluation and Documentation

### 36. `evaluation/results.csv`
Stores experimental results, including model metrics, image size, deployment configuration, replica counts, CPU utilization, response time, and scaling behavior.

### 37. `README.md`
Documents the project overview, problem statement, architecture, technologies, installation, model training, API usage, Docker commands, Kubernetes deployment, autoscaling, monitoring, evaluation, and limitations.

### 38. `LICENSE`
Defines the project's open-source license and usage permissions.

---

## Phase 9: End-to-End Testing and Final Refinements

### 39. Machine Learning Testing
Verifies that the trained model loads successfully and produces valid predictions.

### 40. API Integration Testing
Tests the complete prediction workflow through FastAPI and verifies request validation and error handling.

### 41. Docker Integration Testing
Builds and runs the Docker image and verifies that the container serves predictions correctly.

### 42. Kubernetes Integration Testing
Deploys the application and verifies pod readiness, service connectivity, configuration, and application health.

### 43. Autoscaling Testing
Generates increasing workloads and verifies that HPA scales application replicas up and down as expected.

### 44. Monitoring Verification
Checks Prometheus metrics collection and Grafana dashboard functionality.

### 45. Final GitHub Preparation
Reviews the repository structure, removes temporary files and secrets, updates documentation, and pushes the tested project to GitHub.

---

## Development Rule

Implement all files in the order listed above.

1. Create one file at a time.
2. Understand the purpose of every file before implementing it.
3. Execute and test each component before proceeding to the next.
4. Maintain clean, modular, reusable Python code.
5. Use Docker for application containerization.
6. Use Kubernetes for deployment, service discovery, and autoscaling.
7. Verify all Kubernetes resources using `kubectl`.
8. Record actual experimental results instead of using fabricated measurements.
9. Keep the project reproducible and suitable for GitHub portfolio presentation.
10. Do not skip testing or move to the next phase until the current phase works.

**Development objective:** Build a complete, locally reproducible machine learning model-serving platform using Python, FastAPI, Docker, Kubernetes, Horizontal Pod Autoscaling, Prometheus, and Grafana.

**Important:** This project should demonstrate a working end-to-end MLOps deployment workflow rather than simply contain configuration files.
